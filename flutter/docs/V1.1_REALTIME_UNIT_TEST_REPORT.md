### 2.2 RealtimeClient 核心行为

- **传输层**: `StreamChannel<dynamic>`（通过 `channelFactory` 注入，生产默认 `IOWebSocketChannel`）
- **认证**: `Authorization: Bearer <token>` header，token 不放在 URL 中
- **状态机**: `disconnected → connecting → authenticating → connected`；重连时为 `reconnecting → authenticating → connected`
- **心跳**: 收到 `connection.ping` → 回复 `connection.pong`
- **重连**: 指数退避 `[1, 2, 4, 8, 16]` 秒，cap 在 16s；`connection.ready` 重置 `_reconnectAttempts=0`
- **Token 过期**: `connection.error` + `code=WS_AUTH_FAILED` → 调用 `onTokenExpired()` 刷新 → 成功则重连，失败则 `error` 状态 + 调度重连
- **事件分发**: `onEvent` 回调 + `addEventListener` 多播监听器

### 2.3 ConnectionState 枚举

```dart
enum ConnectionState { disconnected, connecting, authenticating, connected, reconnecting, error }
```

- `isConnected` getter: 仅 `connected` 为 true

### 2.4 EventEnvelope Schema

```dart
{
  "type": String,      // 必填，默认 ''
  "id": String,        // 可选，默认 ''
  "timestamp": String, // 可选，默认 ''
  "payload": Map       // 可选，默认 {}
}
```

- `fromJson` 对所有字段使用 `as String? ?? ''` / `as Map? ?? {}` 容错
- `pong()` / `close()` 静态方法构造客户端→服务端事件

## 3. Channel Factory Injection

### 3.1 注入点

```dart
final StreamChannel<dynamic> Function(
  Uri uri, {
  Map<String, String> headers,
}) channelFactory;
```

- 生产默认: `_defaultChannelFactory` → `IOWebSocketChannel.connect(uri, headers: headers)`
- 测试注入: `FakeChannelFactory.call` → 返回内存 `FakeWebSocketChannel`

### 3.2 为什么用 StreamChannel 而非 WebSocketChannel

`web_socket_channel 3.x` 将 `WebSocketChannel` 改为 `abstract interface class`，包含大量 `StreamChannelMixin` 抽象成员（`cast` / `changeSink` / `changeStream` / `pipe` / `transformStream` / `transformSink` 等），无法在测试内合法继承。

`RealtimeClient` 实际只依赖 `StreamChannel` 的两个核心成员：
- `stream.listen(...)` — 接收服务端消息
- `sink.add(...)` / `sink.close()` — 发送消息 / 关闭连接

因此将 `channelFactory` 类型定为 `StreamChannel<dynamic>`，生产 `IOWebSocketChannel` 通过 `StreamChannelMixin` 满足该契约，行为不变。

## 4. Fake Channel Design

### 4.1 FakeWebSocketSink

实现 `StreamSink<dynamic>` 完整接口：

| 方法 | 行为 |
|------|------|
| `add(data)` | 追加到 `sent` 列表（closed 后忽略） |
| `addError(error, [stackTrace])` | no-op |
| `addStream(stream)` | 遍历 stream 并 add |
| `close()` | 设 `closed=true`，完成 `done` Future |
| `done` | Completer 驱动的 Future |

测试通过 `sentMessages` getter 读取客户端发出的消息，通过 `isSinkClosed` 验证关闭。

### 4.2 FakeWebSocketChannel

使用 `with StreamChannelMixin<dynamic>`（提供 `cast`/`changeSink`/`pipe` 等工具方法的默认实现），只需覆盖 `stream` 和 `sink`：

- `_incoming`: `StreamController<dynamic>` — 模拟服务端→客户端
- `_sink`: `FakeWebSocketSink` — 捕获客户端→服务端

测试辅助方法：

| 方法 | 用途 |
|------|------|
| `emit(message)` | 模拟服务端发送消息 |
| `emitError(error)` | 模拟服务端发送错误事件 |
| `closeServer()` | 模拟服务端关闭连接（触发 onDone） |
| `sentMessages` | 读取客户端发出的所有消息 |
| `isSinkClosed` | 检查客户端是否关闭了 sink |

### 4.3 FakeChannelFactory

| 成员 | 用途 |
|------|------|
| `channels` | 所有创建的 FakeWebSocketChannel 列表 |
| `uris` | 每次调用的 URI 记录 |
| `headersHistory` | 每次调用的 headers 记录 |
| `throwOnCall` | 非 null 时每次调用抛此异常（用于 connection failure 测试） |
| `callCount` | 工厂调用次数 |

方法签名严格匹配 `channelFactory` 类型：
```dart
StreamChannel<dynamic> call(Uri uri, {Map<String, String> headers = const {}})
```

## 13. Backoff Tests

使用 `fake_async` 包的 `FakeAsync().run()` 控制虚拟时间，避免真实等待数秒。

| 测试 | 验证内容 |
|------|----------|
| 连续失败遵循 1/2/4/8/16s 退避序列，第 6 次起 cap 在 16s | 6 次连续 drop（不发 ready 以避免重置计数器），验证每次重连时机分别为 ~1s/~2s/~4s/~8s/~16s/~16s |
| connection.ready 重置 _reconnectAttempts，下次退避回到 1s | 首次 drop → 1s 重连 → emit ready（重置计数器） → 第二次 drop → 再次 1s（而非 2s） |

**关键设计**: 退避序列测试中**不发送 `connection.ready`**，因为 `_onMessage` 中 `connection.ready` 会执行 `_reconnectAttempts = 0`，重置退避计数器。连续失败场景下保持 authenticating 状态即可持续递增。

## 16. Production Code Defect

### DEFECT-001: EventEnvelope.fromJson 对非 String type 字段抛出未捕获异常

**严重程度**: Medium
**状态**: 记录，未修复（本轮禁止修改生产代码）

#### 复现步骤

1. RealtimeClient 已连接（state = connected）
2. 服务端发送 `{"type": 123}`（type 为 int 而非 String）
3. `_onMessage` 中 `jsonDecode` 成功，`as Map<String, dynamic>` 成功
4. `EventEnvelope.fromJson(data)` 执行 `data['type'] as String?` → 对 int 值抛出 `TypeError`
5. 该异常**不在** `_onMessage` 的 try-catch 范围内（try-catch 仅包裹 `jsonDecode`）
6. 异常在 stream `onData` 回调中被 zone 报告为 uncaught error

#### 实际影响

- 客户端 subscription **不被取消**（`cancelOnError: false`，且异常不是 stream error event）
- 客户端 state 保持 `connected`
- 后续合法消息**仍可正常处理**
- 但 uncaught error 会被 zone 报告，在生产环境可能导致 crash 或被全局错误处理器捕获

#### 根因

```dart
// realtime_client.dart _onMessage
void _onMessage(dynamic raw) {
  late final Map<String, dynamic> data;
  try {
    data = jsonDecode(raw as String) as Map<String, dynamic>;
  } catch (_) {
    return;  // 仅捕获 jsonDecode 异常
  }
  final evt = EventEnvelope.fromJson(data);  // ← 无 try-catch，可能抛出
  ...
}
```

#### 建议修复方向（不在本轮执行）

将 `EventEnvelope.fromJson` 调用纳入 try-catch，或在 `EventEnvelope.fromJson` 内部对 type 字段做更安全的类型转换（如 `'${data['type']}'`）。

#### 测试覆盖

测试 `type 字段为 int 时 EventEnvelope.fromJson 抛出未捕获异常` 使用 `runZonedGuarded` 捕获 uncaught error，验证：
1. 确实存在 uncaught error（缺陷复现）
2. 客户端 state 保持 connected（subscription 未取消）
3. 后续合法消息仍可正常处理

## 17. Test Isolation

- **独立创建**: 每个测试独立创建 `RealtimeClient`、`FakeChannelFactory`、`FakeWebSocketChannel`

## 21. Known Limitations

1. **PRODUCTION CODE DEFECT (DEFECT-001)**: `EventEnvelope.fromJson` 对非 String type 字段抛出未捕获异常。已记录并复现，未修复（本轮禁止修改生产代码）。
2. **Runtime 验证**: 本轮为纯单元测试，不涉及真实 WebSocket 连接、真实后端或真机运行。
3. **Android**: Android SDK 仍缺失，本轮明确不处理。
4. **Fake channel 局限性**: FakeWebSocketChannel 使用单订阅 StreamController，不模拟真实 WebSocket 的帧分片、ping/pong 帧、close code 等底层细节。但 RealtimeClient 只依赖 StreamChannel 的 stream/sink 抽象，这些底层细节不影响客户端逻辑测试。
5. **onEvent 回调异常**: 未测试 `onEvent` 回调本身抛异常的场景（属于调用方责任，非 RealtimeClient 内部逻辑）。
