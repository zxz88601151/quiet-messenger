## 1. Defect Description

### DEFECT-002: id / timestamp 字段使用 `as String?` 强制转换

**位置**: `lib/core/realtime/event_envelope.dart` — `EventEnvelope.fromJson`

**描述**: `id` 和 `timestamp` 字段使用 `data['id'] as String? ?? ''` 和 `data['timestamp'] as String? ?? ''`。当服务端发送 `{"type": "valid", "id": 123}` 或 `{"type": "valid", "timestamp": {}}` 时，`as String?` 对非 String 值抛出 `TypeError`，异常逃逸到 RealtimeClient 的 stream onData 回调所在的 Dart zone。

**触发示例**:
```json
{"type": "message.new", "id": 123}
{"type": "message.new", "timestamp": {"nested": true}}
{"type": "message.new", "id": [1, 2, 3]}
```

### DEFECT-003: payload 字段使用 `as Map<String, dynamic>?` 强制转换

**位置**: `lib/core/realtime/event_envelope.dart` — `EventEnvelope.fromJson`

**描述**: `payload` 字段使用 `(data['payload'] as Map<String, dynamic>?) ?? <String, dynamic>{}`。当服务端发送 `{"type": "valid", "payload": "not-a-map"}` 或 `{"type": "valid", "payload": 42}` 时，`as Map<String, dynamic>?` 对非 Map 值抛出 `TypeError`。

**触发示例**:
```json
{"type": "message.new", "payload": "string-instead-of-map"}
{"type": "message.new", "payload": [1, 2, 3]}
{"type": "message.new", "payload": true}
```

### 共同影响

- 异常在 stream `onData` 回调中被 zone 报告为 uncaught error
- 客户端 subscription 不被取消（`cancelOnError: false`），state 保持 connected
- 后续合法消息仍可正常处理
- 但 uncaught error 在生产环境可能导致 crash 或被全局错误处理器捕获

## 2. Root Cause

与 DEFECT-001 相同的根因模式：`EventEnvelope.fromJson` 对所有字段使用 Dart `as` 强制类型转换，对类型不匹配的值抛出运行时 `TypeError`。该异常不在 `RealtimeClient._onMessage` 的 try-catch 范围内（try-catch 仅包裹 `jsonDecode`）。

```dart
// 修复前（DEFECT-001 已修复 type，DEFECT-002/003 仍存在）
return EventEnvelope(
  type: type as String? ?? '',           // ✅ DEFECT-001 已修复
  id: data['id'] as String? ?? '',        // ❌ DEFECT-002
  timestamp: data['timestamp'] as String? ?? '',  // ❌ DEFECT-002
  payload: (data['payload'] as Map<String, dynamic>?) ?? {},  // ❌ DEFECT-003
);
```

## 4. Fix Strategy

与 DEFECT-001 完全一致的策略：

1. **类型安全检查**: 对每个字段使用 `is!` 显式类型检查替代 `as` 强制转换
2. **null 兼容**: 字段为 null（缺失）时保留原有默认值行为（id/timestamp → `''`，payload → `{}`）
3. **特定异常**: 非 null 且类型不匹配时抛出 `FormatException`（含字段名和实际 runtimeType 便于调试）
4. **统一捕获**: `RealtimeClient._onMessage` 中已有的 `try { ... } on FormatException { return; }` 自动覆盖所有字段
5. **不改变正常行为**: 合法类型字段的解析路径完全不变

### 为什么不在 fromJson 中直接 `toString()`

将 `123` 转为 `"123"` 会改变协议语义——服务端发送非法类型字段是协议违规，不应被静默修正后分发。正确行为是视为 malformed event 并忽略，与非 JSON 消息处理一致。

### 为什么用 `FormatException` 而非自定义异常

- Dart 标准库异常，语义为"数据格式不符合预期"
- 不需要新增自定义异常类，最小化变更
- `_onMessage` 中 `on FormatException` 精确捕获，不影响其他异常类型

## 5. Code Changes

### EventEnvelope.fromJson (`lib/core/realtime/event_envelope.dart`)

**修改前**:
```dart
factory EventEnvelope.fromJson(Map<String, dynamic> data) {
  final dynamic type = data['type'];
  if (type != null && type is! String) {
    throw FormatException(
      'EventEnvelope.type must be a String or null, got ${type.runtimeType}',
    );
  }
  return EventEnvelope(
    type: type as String? ?? '',
    id: data['id'] as String? ?? '',
    timestamp: data['timestamp'] as String? ?? '',
    payload: (data['payload'] as Map<String, dynamic>?) ?? <String, dynamic>{},
  );
}
```

**修改后**:
```dart
factory EventEnvelope.fromJson(Map<String, dynamic> data) {
  final dynamic type = data['type'];
  final dynamic id = data['id'];
  final dynamic timestamp = data['timestamp'];
  final dynamic payload = data['payload'];

  // 全字段类型安全检查（DEFECT-001/002/003）：
  // 字段为 null（缺失）时兼容默认值，与既有行为一致；
  // 非 null 且类型不匹配时视为 malformed envelope，抛出 FormatException
  // 由调用方（RealtimeClient._onMessage）捕获并静默忽略。
  // 原 as String? / as Map? 对非匹配类型抛出未捕获 TypeError。
  if (type != null && type is! String) {
    throw FormatException(
      'EventEnvelope.type must be a String or null, got ${type.runtimeType}',
    );
  }
  if (id != null && id is! String) {
    throw FormatException(
      'EventEnvelope.id must be a String or null, got ${id.runtimeType}',
    );
  }
  if (timestamp != null && timestamp is! String) {
    throw FormatException(
      'EventEnvelope.timestamp must be a String or null, got ${timestamp.runtimeType}',
    );
  }
  if (payload != null && payload is! Map<String, dynamic>) {
    throw FormatException(
      'EventEnvelope.payload must be a Map or null, got ${payload.runtimeType}',
    );
  }

  return EventEnvelope(
    type: type as String? ?? '',
    id: id as String? ?? '',
    timestamp: timestamp as String? ?? '',
    payload: payload as Map<String, dynamic>? ?? <String, dynamic>{},
  );
}
```

**关键变更点**:
- 新增 `id`、`timestamp`、`payload` 三个局部变量提取
- 新增 3 个 `is!` 类型安全检查（id/timestamp/payload）
- 构造函数中 `data['id']` → `id`、`data['timestamp']` → `timestamp`、`data['payload']` → `payload`（避免重复 lookup，且经过类型检查后 `as` 转换安全）
- type 字段检查逻辑不变（DEFECT-001 已修复）

### 6.1 DEFECT-002: id/timestamp 非 String 类型

覆盖场景：
- `id` 为 int: `{"type": "message.new", "id": 123}`
- `id` 为 object: `{"type": "message.new", "id": {"x": 1}}`
- `id` 为 array: `{"type": "message.new", "id": [1, 2]}`
- `timestamp` 为 int: `{"type": "message.new", "timestamp": 123456}`
- `timestamp` 为 object: `{"type": "message.new", "timestamp": {"nested": true}}`
- `timestamp` 为 array: `{"type": "message.new", "timestamp": [1, 2, 3]}`

**预期**: 全部无 uncaught error，消息不被分发（视为 malformed），客户端保持 connected。

### 6.2 DEFECT-002: id/timestamp 为 null

```json
{"type": "message.new", "id": null, "timestamp": null, "payload": {"text": "hi"}}
```

**预期**: 无 uncaught error，消息被分发，`id=''`、`timestamp=''`（既有行为保留）。

### 6.3 DEFECT-003: payload 非 Map 类型

覆盖场景：
- `payload` 为 int: `{"type": "message.new", "payload": 123}`
- `payload` 为 string: `{"type": "message.new", "payload": "not-a-map"}`
- `payload` 为 array: `{"type": "message.new", "payload": [1, 2, 3]}`
- `payload` 为 bool: `{"type": "message.new", "payload": true}`

**预期**: 全部无 uncaught error，消息不被分发（视为 malformed），客户端保持 connected。

### 6.4 DEFECT-003: payload 为 null

```json
{"type": "message.new", "id": "msg_001", "payload": null}
```

**预期**: 无 uncaught error，消息被分发，`payload={}`（既有行为保留）。

### 6.5 全字段 malformed 后后续消息恢复（post-error recovery）

流程：
1. 客户端连接并 ready
2. 连续发送 4 种全字段 malformed 事件（id:int、timestamp:object、payload:string、id:array+payload:int）
3. 验证：客户端保持 connected，所有 malformed 均未分发，无 uncaught error
4. 发送合法事件 `{"type": "message.new", "id": "msg_recovery", ...}`
5. 验证：合法事件被正确处理（type/id/timestamp/payload 全部正确）
