**Status:** FIXED

## 1. Executive Summary

审计发现离线消息同步存在真实缺陷：MessageNotifier（Android）和 MessageController（Desktop）未订阅 RealtimeClient 状态变化，WebSocket 重连后不自动拉取历史消息，导致用户在 Chat 页面期间断网收到的消息无法自动恢复（需退出重进 Chat 或重启 App）。

已修复：添加 RealtimeClient state listener，disconnected→connected 时自动 reconcile（拉取最新历史 + 合并本地 failed/sending 消息 + 按 id 去重 + 按时间排序）。

## 5. WebSocket 重连后消息同步（核心缺陷）

### 缺陷描述

```
用户在 Chat 页面
    ↓
网络断开 → WebSocket disconnect
    ↓
对方发送消息 → 后端持久化 → WS 发送失败（用户离线）
    ↓
网络恢复 → WebSocket reconnect
    ↓
MessageNotifier 无状态监听 → 不调用 load()
    ↓
❌ 离线消息丢失（直到退出重进 Chat 或重启 App）
```

### Root Cause

`MessageNotifier`（Android）和 `MessageController`（Desktop）**没有订阅 RealtimeClient 状态变化**。

这与 FriendNotifier（DEF-RT-010 已修复）的问题相同，但 MessageNotifier 遗漏了。

### 证据

- `MessageNotifier` 构造函数仅调用 `_realtime.addEventListener(_onEvent)`（事件监听）
- 没有 `_realtime.addStateListener(...)`（状态监听）
- `load()` 仅在 `_ChatBody.initState` 中调用一次
- WebSocket reconnect 后无任何触发机制调用 `load()`

## 6. 消息同步竞态检查

| 检查项 | 状态 | 说明 |
|--------|------|------|
| History + WS 同时到达 | ✅ 安全 | `_upsert` 按 message.id 去重 |
| History 覆盖 WS 事件 | ⚠️ 已修复 | `load()` 原 `_messages = page` 直接覆盖；reconcile 改为合并 |
| 重复消息 | ✅ 无 | id 去重 |
| 消息丢失 | ✅ 无 | reconcile 保留 failed/sending 消息 |
| 顺序错误 | ✅ 修复 | reconcile 后按 created_at 排序 |

### 原有竞态（修复前）

`load()` 执行期间，如果 WS 事件到达：
1. `_upsert` 将 WS 消息加入 `_messages`
2. `load()` 完成后 `_messages = page` 覆盖
3. WS 消息丢失（但消息在 DB 中，REST 响应包含它 → 实际不丢失）

修复后 reconcile 采用合并策略，完全消除此竞态。

## 8. 修复内容

### 8.1 Android — `message_notifier.dart`

**新增：**
- `_unsubscribeState` — 状态监听器取消函数
- `_hasBeenConnected` / `_wasDisconnected` / `_reconciling` — 重连守卫标志
- `_onConnectionState(state)` — RealtimeClient 状态监听器
- `_reconcile()` — 离线消息 catch-up 方法

**`_onConnectionState` 逻辑：**
- `connected` + `_hasBeenConnected` + `_wasDisconnected` + `!_reconciling` → 调用 `_reconcile()`
- 首次 connect 不触发（`_hasBeenConnected = false`）
- `disconnected`/`reconnecting` → 设置 `_wasDisconnected = true`

**`_reconcile` 逻辑：**
1. 保存本地 failed 和 sending 消息
2. 调用 `_repo.getMessages()` 获取最新 50 条
3. `_messages = List.from(page)` 替换为服务器消息
4. 重新追加 failed/sending 消息（按 id 去重）
5. 按 created_at 排序
6. `notifyListeners()`

**修改：**
- 构造函数添加 `_realtime.addStateListener(_onConnectionState)`
- `dispose()` 添加 `_unsubscribeState?.call()`

### 8.2 Desktop — `message_state.py`

**与 Android 相同的修复模式：**
- `_unsubscribe_state` — 状态监听器取消函数
- `_has_been_connected` / `_was_disconnected` / `_reconciling` — 守卫标志
- `_on_connection_state(state)` — 状态监听器
- `_reconcile()` — catch-up 方法
- 构造函数添加 `add_state_listener`
- `dispose()` 添加状态监听取消

### 8.3 Desktop 测试辅助 — `test_messages.py`

**FakeRealtime 新增：**
- `add_state_listener(cb)` — 返回空取消函数（测试不需要状态触发）
