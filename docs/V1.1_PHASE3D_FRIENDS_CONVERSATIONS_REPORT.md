## 3. User Search

- 后端 `GET /users/search?q=`：username/phone 模糊搜索，phone 仅精确或后缀匹配（防泄露）。
- 返回字段仅 `id/username/nickname/avatar`（UserSearchItem），**不含 password/phone/tokens/device_id/internal**（授权§11）。
- Flutter `FriendRepository.searchUsers` / Desktop `FriendRepository.search_users` 真实调用，UI 仅展示公开字段。

## 4. Friend Request

- `POST /friends/requests` → `{target_username_or_phone}`。
- 后端校验：自加自己 → 400；不存在 → 404；已是好友 → 201（返回既有 friendship+conversation，**不建重复关系**）；同方向 pending → 409 DUPLICATE_REQUEST；反向 pending → 409（对方已发请求）。
- 双端 Repository 真实映射 `FriendRequest`（含 `isIncoming` 方向判定，基于 viewerId）。

## 5. Accept / Reject

- Accept（`POST /friends/requests/{id}/accept`）：建立双向 Friendship（A→B + B→A）+ 预创建规范化 Conversation（user_a=min, user_b=max）→ 返回 `{friendship, conversation}`。
- Reject（`POST .../reject`）：status → rejected（终态不可逆，再 accept → 409 CONFLICT）。
- 仅接收方可 accept/reject（sender 操作 → 404，授权§24）。
- 双端 `FriendNotifier.accept` / `FriendController.accept` 暴露 `lastAcceptedConversationId` 供导航。

## 6. Friend List

- `GET /friends` → 好友列表（含 friendship_created_at）。仅当前用户自己的好友（授权§24）。
- 双端真实消费 `Friendship.user`（friend 侧），UI 展示昵称/@username。

## 7. Delete Friend

- `DELETE /friends/{id}`：移除双向 Friendship，**保留历史消息**（后端行为，V1 推荐）；删除后发消息 → 403 FRIEND_REQUIRED（非 3D 范围，但后端已验证）。
- 不存在好友 → 404 FRIEND_NOT_FOUND。

## 8. Friendship Constraints

- **双向唯一**：`Friendship` 表 `UNIQUE(user_id, friend_id)`；accept 时双向写入，幂等（已存在跳过）。
- **防自关系**：`create_friend_request` 校验 `target == sender.username/phone` → 400（授权§10）。
- **重复请求防护**：`FriendRequest` 表 `UNIQUE(sender_id, receiver_id)`。
- **A→B 与 B→A 不重复**：service 层 `_add_friendship` 查重；Friendship 是定向边（A→B 与 B→A 各一条，语义正确，非「两个独立好友关系」）。

## 9. Conversation Model

- `Conversation`（DIRECT only）：`id / user_a / user_b / created_at / updated_at`。
- `ConversationType` 枚举：DIRECT / GROUP / CHANNEL / COMMUNITY / BROADCAST（授权§13），**V1.1 仅实现 DIRECT**，其余为类型预留、未使用。

## 10. Direct Conversation

- 一对一会话。`GET /conversations` 返回当前用户参与的所有 DIRECT 会话（含 peer / last_message / unread_count）。
- Friend→Chat 导航：Accept 时已预创建 Conversation，客户端用 `conversationId` 导航进入（授权§15/§19，ChatPage 仅空状态入口，不发消息）。

## 11. Conversation Uniqueness

- `Conversation` 表 `UNIQUE(user_a, user_b)`（user_a=min, user_b=max 规范化）。
- 重复 accept / 重复加好友 → **返回同一 C001，不产生 C002**（真实验证 §F 确认）。
- 数据库层唯一性约束兜底（授权§14）。

## 19. Dual Client Verification

- 证明：同一 Conversation 被双端看到，Friend→Chat 稳定进入同一会话。
