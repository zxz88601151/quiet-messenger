### Tag Finalization Strategy（需人工确认）

**选项 A：移动 v1.1.0 tag 到最终 commit**
- 前提：v1.1.0 尚未正式对外发布
- 操作：`git tag -d v1.1.0 && git tag -a v1.1.0 f438799 -m "..."` && `git push origin --tags --force`
- 风险：如果已有人基于旧 tag 做了引用，会造成混乱
- 适用：tag 仅内部使用，未公开发布

**选项 B：保留 v1.1.0，创建 v1.1.1**
- 前提：v1.1.0 已对外发布，或不想移动已有 tag
- 操作：`git tag -a v1.1.1 f438799 -m "V1.1.1 — Desktop refinement + version alignment"`
- 优点：不破坏已有 tag，语义化版本
- 缺点：v1.1.0 指向不完整的代码

**选项 C：保留 v1.1.0 作为 "Core Release"，最终 Release 使用新 tag**
- v1.1.0 = 核心通信功能初始 Release（959fca7）
- v1.1.1 或 v1.1.0-final = 包含 Phase 2 修复的最终 Release
- 优点：保留历史语义
- 缺点：版本号可能混淆

**RELEASE TAG: NEEDS DECISION**

**禁止：** 未经人工确认移动 tag、force push、删除 tag、擅自选择版本号。
