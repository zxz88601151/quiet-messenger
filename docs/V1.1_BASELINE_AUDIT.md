## G. 风险

| 风险 | 等级 | 说明 | 缓解 |
|------|------|------|------|
| 从零实现，契约量大 | 中 | 三端 + 后端需同时对齐，易漂移 | 以 shared/ 为单一事实源，每 Phase 对照契约自检 |
| 客户端本地态易误入服务端 | 高 | sending/failed/waiting_network/sync_status 易被误存 DB | DATA_MODEL 已冻结禁止新增 Message.status；实施时严禁 |
| privacy 对等原则服务端实时读取 | 中 | 广播 message.read/typing 前需查双方设置 | 服务端缓存 privacy_settings，更新延迟 ≤5s（DATA_MODEL §1 约束） |
| 离线发送手动重发 UX | 低 | 用户可能不理解"待发送" | Network Status 顶部提示文案需明确 |
| index.html 删除项归属 | 低 | 删除项在原型，不在代码 | 待你授权 PROTOTYPE UPDATE，不擅自改 |
| 三端同步 privacy 设置 | 中 | 一设备改设置，他设备需拉取 | 改后 PATCH 成功即更新本地；他设备下次 GET /users/me 或 WS 事件触发刷新（WS 未定义 privacy.updated 事件，需约定拉取时机） |

**G-补充（需你拍板）**：WS 协议未定义 `privacy.updated` 广播事件。多设备间隐私设置同步依赖"他设备下次主动 GET /users/me"或重新登录。若要求实时同步，需新增 WS 事件——但这属于"新增 WS event"，按指令第十八节需先报告。建议 V1.1 暂用"他设备下次进入前台/网络恢复时 GET /users/me 拉取"兜底，不新增 WS 事件。
