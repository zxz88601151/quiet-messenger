## 四、修复清单（最小改动，单方向）

### 4.1 app.dart（#85，构建断点）
1. **初始化顺序**（late final 读前赋值崩溃）：改为 tokenStorage → api → authRepo → auth → realtime 单方向。
2. **`baseUrl` 未定义**（error #1）：ApiClient 无 `baseUrl` getter；caller 改用真实来源 `ApiConfig.apiBaseUrl`（新增 import）。
3. **`getToken` Future vs sync**（error #2）：`TokenStorage.getAccessToken()` 为 async；改为 `_accessToken` 可变字段，由 `getToken: () => _accessToken` 同步闭包读取，token 在 `_loadTokenAndConnect()` 中 `await` 后填充再 `connect()`。**无 sync-over-async hack，token 生命周期正确**。
4. **运行时回归修复**：初版将 `_realtime` 赋值移入 async 方法，导致 `build()` 首帧访问未初始化字段（`LateInitializationError`，widget_test 失败）。已修正为 `initState` 内同步创建 `RealtimeClient`，connect 延后到 token 加载后。

### 4.2 Friends UI（#86，用真实模型，未删 UI）
- `add_friend_page.dart`：3× `Undefined name 'name'` → 改用 `user.username`（UserSummary 真实字段）。
- `friend_requests_page.dart`：`_accept`/`_reject` 增加 `FriendRequest request` 参数（原方法体内 `request`/`name` 越界未定义），调用点传入 `request`，snackbar 内本地派生显示名。
- `friends_page.dart`：`textSecondary` 不存在 → 真实次要文字色 `AppColors.text2`；顺带消除 `const` 非法（修复 Invalid constant value）。

### 4.3 测试文件（#87，Fake 匹配真实接口）
- `friend_repository_test.dart`：
  - 包名错误 `package:liaotianapp/...` → 真实包名 `flutter_client` **相对路径导入**（与 chat 测试一致）。
  - `_FakeAdapter extends HttpClientAdapter` → `implements HttpClientAdapter`（Dio 3 interface 化）。
  - 缺 `import 'dart:typed_data'` → 补（解决 Uint8List）。
  - `_json(Object body)` → 放宽参数类型为 `Object`（后端依端点返回 Map 或 List）。
- `realtime_client_test.dart`：
  - 原 `FakeWebSocketChannel extends WebSocketChannel` 因 web_socket_channel 3.x 将 WebSocketChannel 改为 interface class（含大量 StreamChannelMixin 抽象成员）无法合法实现，且该 Fake 从未被注入（RealtimeClient 内部用 IOWebSocketChannel.connect）。移除死代码 Fake，保留 3 个真实断言（状态枚举 / EventEnvelope 解析 / 退避上限）。

## 八、Release Security 审计（P1，仅报告不 redesign）

- **发现 P1（可接受于 dev/staging，禁止进 prod）**：`ApiConfig` 的 development (`http://127.0.0.1:8000`) 与 staging (`http://192.168.3.200:9080`) 使用明文 `http://`。文档明确声明「do NOT forge HTTPS」用于本地验证，Production 不硬编码、须由 build env/runtime 注入。
- **无强制降级漏洞**：`RealtimeClient._wsUri()` 遵循 base URL scheme（`https→wss`，仅 `http` base 时才 `ws`），不存在把 `https` base 强制降为 `ws://` 的逻辑。
- **建议（非本阶段范围）**：发布 Production 前，ApiConfig 必须注入 `https://` 域名；CI 增加「staging/prod build 不得含 http:// base」的断言。
