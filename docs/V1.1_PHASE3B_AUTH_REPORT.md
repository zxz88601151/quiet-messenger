## 1. Phase 3B Scope

**目标**：让双端客户端第一次真正完成「身份 → 登录 → Token → Session → 退出」完整闭环，且真实经过 Backend（FastAPI，Phase 2B 已 PASS）。

**本次实现范围**：
- 统一 Auth Domain Model（User / AuthTokens / Session / AuthState）—— 双端
- 真实 `AuthRepository`（register / login / refresh / logout / restoreSession / getCurrentUser / forgotPassword / resetPassword）—— 双端，复用 Phase 3A 的 `ApiClient` / `TokenStorage`

- Token 安全持久化（flutter_secure_storage / keyring）—— 双端

## 6. Token Storage

| 端 | 机制 | 位置 |
| --- | --- | --- |
| Flutter | `flutter_secure_storage`（系统密钥库，非 SharedPreferences/明文） | `core/storage/token_storage.dart` |
| Desktop | `keyring` + 内存降级（headless 无 keyring 时） | `storage/token_storage.py` |

流程：
```
Login → Backend 返回 token → setTokens(access,refresh) → AuthState=authenticated
App 启动 → 读安全存储 → 有 refresh → refresh() 续期 → GET /users/me → authenticated
Logout → POST /auth/logout → clear() → AuthState=unauthenticated → /login
```

**未明文存储、未放 UI State、未用 SharedPreferences**（满足 §7）。

---

## 7. Session Restore

双端 `restoreSession()` 逻辑一致：
1. 读安全存储 refresh_token
2. 无 → 返回 None（unauthenticated）
3. 有 → 调 `refresh()` 轮换 + 拉 `GET /users/me`
4. 成功 → Session 恢复（authenticated）
5. refresh 失败（过期/吊销）→ 清本地 token → None（unauthenticated）

App 启动 `AuthNotifier.restore()` / `AuthController.restore()` 驱动初始路由。

---

## 8. Logout

双端：调用 `AuthRepository.logout()` → POST `/auth/logout`（后端吊销 refresh + device）→ 本地 `clear()` → AuthState=unauthenticated → 路由回 /login。后端失败仍清本地（defense in depth）。Desktop 在侧栏「退出登录」项触发；Flutter 在 Settings 页「退出登录」项触发（最小入口，未重做 Profile/Settings）。

---

## 9. Error Handling

统一 Error Mapper（双端），后端 code → 用户文案：
- `INVALID_CREDENTIALS` → 「用户名或密码错误，请重试」
- `VALIDATION_ERROR` → 「输入有误：<msg>」
- `UNAUTHENTICATED` / `FORBIDDEN` → 「登录已失效，请重新登录」
- `NETWORK_ERROR` → 「网络异常，请检查连接后重试」
- 其他 → 后端 message 或通用提示

**UI 禁止显示**：DioException / Python traceback / HTTP 状态码 / 实现细节。所有异常经 Mapper 转用户语言。

| 状态 | Flutter (go_router) | Desktop |
