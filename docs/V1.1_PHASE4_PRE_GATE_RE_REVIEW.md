### 3.2 web_socket_channel 真实定义（查 pub cache）

```
FILE: .../Pub/Cache/hosted/pub.dev/web_socket_channel-3.0.3/lib/src/channel.dart
L25: abstract interface class WebSocketChannel extends StreamChannelMixin

```

确认：`WebSocketChannel` 与 `WebSocketSink` 在 3.0.3 均为 **`abstract interface class`**。`WebSocketChannel` 继承 `StreamChannelMixin`，后者带有大量抽象成员（`cast`/`changeSink`/`changeStream`/`pipe` 等）。

### 3.3 兼容性判定

- 无法在测试内 `extends WebSocketChannel`（interface class，且混合成员过多无法手动实现）。
- 也无法用「`implements WebSocketChannel` + 手写 `_FakeSink implements WebSocketSink`」低成本实现（mixin 抽象成员爆炸）。
- 更关键：**`RealtimeClient` 内部使用 `IOWebSocketChannel.connect`，没有可注入的 channel 工厂**，Fake 即便实现也无法被测试驱动。

**结论：`FakeWebSocketChannel compatibility: N/A（已删除）`。删除正确** —— 它是无法工作的 dead scaffolding，且从未被注入 client、未参与任何 assertion（见 §8）。删除不影响测试覆盖范围（原 3 个 realtime 测试本来就不依赖它）。
