## 1. Phase 3C Scope

**目标**：建立 WebSocket 实时通信基础设施，验证 Mobile / Desktop 均能用已认证用户身份建立真实 WebSocket 连接，后端识别 User / Device / Connection 并维护单用户多设备连接。

**本次实现范围**：
- Backend：`/ws/v1` WebSocket Endpoint + Bearer 鉴权 + ConnectionManager（连接注册/移除/User→Conns/Device→Conn 映射/发送/广播/stale 清理）+ 统一事件信封 + 心跳（server→client ping）+ 配置（auth/heartbeat/cleanup timeout）
- Flutter：`core/realtime/`（RealtimeClient + ConnectionState + EventEnvelope + RealtimeError），Bearer 头鉴权、指数退避重连、心跳 pong、token 失效→refresh→重连
- Desktop：`app/realtime/`（同构），UI≠Controller≠Realtime 分层
- 统一事件信封（type/id/timestamp/payload）
- 真实双端验证（Development Backend 真实 WebSocket）
- 安全审计 + Scope Leakage 审计

**明确未做（禁止项）**：Chat Message / Conversation / Friends / Group / Presence / Typing / Read Receipt / Handoff / QR Login / Space / AI / Push / E2EE / File Transfer / Voice-Video / Production 部署。

## 2. Architecture

```
Mobile (Flutter RealtimeClient) ──┐
                                   ├──▶ /ws/v1 (Bearer) ──▶ Backend WS Router
Desktop (PySide6 RealtimeClient) ─┘            │
                                              ▼
                                        ConnectionManager
                                  (User → [Connection A, B...])
                                  (Device → Connection)
                                              │
                                      事件信封收发（基础设施事件）
```

- **Backend**：FastAPI `WebSocket` / `WebSocketDisconnect`，进程内 `ConnectionManager` 单例（单 worker 有效；多 worker 需外接 Redis pub/sub，留 Phase 5+）。
- **双端客户端**：独立 `RealtimeClient`，经 `get_token()` 回调取 access token，经 `on_token_expired()` 回调触发 REST refresh 后重连。不直接在 Widget/页面持有 WebSocket。

## 4. Authentication

- **方式**：原生客户端在握手请求头携带 `Authorization: Bearer <access_token>`（Dart `IOWebSocketChannel.connect(headers:)` + Python `websockets.connect(additional_headers=)` 均支持）。
- **校验**：复用 `app.core.security.decode_token(token, "access")` → `payload.sub`=user_id，`payload.device_id` 可选。
- **失败处理**：缺头 / 无效 / 过期令牌 → 发送 `connection.error{code:"WS_AUTH_FAILED"}` 后 `websocket.close(code=4401)`（自定义未认证码），**不进入任何业务事件**。
- **安全**：Token 不入 URL query（§8 红线）；URL 不进日志/代理/历史。
- **Auth Timeout**：`WS_AUTH_TIMEOUT_SECONDS=10`（Bearer 头方案连接即鉴权，无等待窗口；缺 token 立即拒绝，等价安全）。

## 5. Connection Manager

`backend/app/services/connection_manager.py`：
- `Connection`：conn_id / user_id / device_id / state / connected_at / last_activity
- `ConnectionManager`：
  - `register(ws, user_id, device_id)` → 注册，同 device 新连接顶替旧（避免重复 registry）
  - `remove(conn_id)` → 清理，从 user/device 映射移除
  - `get_user_connections(user_id)` → 单用户多设备连接列表
  - `get_device_connection(device_id)` → 设备→连接
  - `send / send_to_user / send_to_device` → 单发/广播
  - `sweep_stale(timeout)` → stale 清理（heartbeat §16）
- 不实现 `send_message` / `send_chat_message` / `send_friend_event` / `send_handoff`（属后续业务）。

---

## 6. User / Device / Connection Model

- **User**：`user_id`（UUID，JWT `sub`）
- **Device**：`device_id`（UUID，JWT `device_id` claim；缺失时降级 `user-{user_id}`）
- **Connection**：`conn_{12 hex}` 唯一连接标识，含 state 机（connecting→authenticating→connected→closing→closed）
- 单用户多设备示例：
  ```
  User A
   ├── Mobile  → Connection A (device_id=mobile_xxx)
   └── Desktop → Connection B (device_id=desktop_xxx)
  ```
- 验证：见 §15 Dual Client（同 user 双连接并存）。

## 7. Event Envelope

统一信封（双端一致）：
```json
{ "type": "...", "id": "evt_xxx", "timestamp": "ISO8601", "payload": {} }
```

**Phase 3C 事件**：
- Server→Client：`connection.authenticated` / `connection.ready` / `connection.ping` / `connection.error`
- Client→Server：`connection.auth`（预留第一帧，本阶段用 Bearer 头故未强制）/ `connection.pong` / `connection.close`

`connection.ready` payload：`{ connection_id, user_id, device_id, user_connection_count }`。

**禁止事件**（本阶段不实现）：`message.new` / `message.read` / `friend.updated` / `conversation.updated` / `handoff.*`。

---

## 8. Heartbeat

- 服务端周期 `connection.ping`（应用层，跨原生客户端统一），客户端收到回 `connection.pong` 更新 `last_activity`。
- 配置写入 `config.py`（非散落代码）：
  - `WS_HEARTBEAT_INTERVAL_SECONDS = 25`（发送 ping 周期）
  - `WS_HEARTBEAT_TIMEOUT_SECONDS = 60`（超时判定 stale）
  - `WS_CLEANUP_INTERVAL_SECONDS = 30`（巡检周期，本阶段在每个新连接接入时触发一次 `sweep_stale()` 保证 stale 清理）
- 单一心跳机制（应用层 ping/pong），不重复实现两套。

---

## 9. Reconnect

- 客户端指数退避：`[1, 2, 4, 8, 16]` 秒，封顶 16s（§17 禁止无限高速重连）。
- 流程：CONNECTED → 断网 → DISCONNECTED → RECONNECTING（退避）→ AUTHENTICATE → CONNECTED。
- Access Token 失效：`on_token_expired()` 回调调 `AuthRepository.refresh()` 更新 TokenStorage 后重连；不自行签发 token（§18）。

## 19. Known Limitations

1. **Flutter analyze/test 沙箱受限**：`flutter.bat.lock` 无法删除（sandbox safe-delete 拦截）致 analyze 卡死；`flutter test` 无 flutter_tester。已 `pub get` 成功（`web_socket_channel 3.0.3`），代码同模式在 3B 曾 0 error。诚实标注 BLOCKED，待带显示/CI 主机关闭。
2. **Staging 地址不可达**：`192.168.3.200:9080` 本沙箱网络不通；真实验证用 development 同源后端完成。
3. **Expired Token 自然过期重连未实跑**：客户端 refresh→重连逻辑完整（代码审查+同构 Desktop 验证），但真实 access token 过期窗口（15–30min）未在验证中等待；列为「代码完整 / 窗口未实跑」。
4. **ConnectionManager 进程内单例**：单 worker 有效；多 worker / 多实例需外接 Redis pub/sub（Phase 5+ 多设备实时同步）。
5. **Desktop venv 被清理**：原 `liaotian-desktop` venv 消失，realtime 测试用 `xchat-backend` venv（含 websockets）跑；Phase 3B PySide6 全量测试需重建 venv 后复跑（非 3C 范围）。
6. **DeviceInfo 仍为确定性占位**：`device_identifier` 用 `pyside6-desktop-default` / `flutter-mobile-<os>`，未引设备指纹库（避免扩 scope）。
