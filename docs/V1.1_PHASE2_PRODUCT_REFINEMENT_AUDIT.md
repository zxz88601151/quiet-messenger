# V1.1 Phase 2 Product Refinement Audit

**Date:** 2026-08-25
**Project:** Quiet Messenger
**Version:** v1.1.0
**Type:** READ-ONLY AUDIT（未修改任何业务代码）

## 1. Executive Summary

Quiet Messenger V1.1 核心通信闭环已完成并发布。本次审计对 12 个领域进行了完整的只读代码审计，重点验证"已有的每一个功能是否真的、稳定地、自然地工作"。

**核心结论：**
- **Backend + Android** 核心能力真实、完整、无硬编码
- **Desktop** 存在多个 P1 级别的 Mock/静态页面问题，是本次审计发现的最大短板
- 无 P0 级别的阻断性缺陷（Desktop offscreen 问题需进一步验证）
- 无安全漏洞
- 测试覆盖良好（Backend 88 / Desktop 36 / Flutter 48）

**最关键发现：**
1. **Desktop DevicesPage 是硬编码 Mock**（"iPhone 15"、"Windows PC"），未接入真实 API
2. **Desktop 无 Profile 页面**，无法查看/编辑个人资料
3. **Desktop SettingsPage 是静态页面**，菜单项点击无反应
4. **Desktop main.py 默认设置 QT_QPA_PLATFORM=offscreen**，可能影响正常 GUI 显示（需验证）

## 3. Session Persistence

**状态：PASS**

| 端 | 存储机制 | 验证 |
|----|----------|------|
| Android | flutter_secure_storage | ✅ Token 加密存储，App 重启自动恢复 |
| Desktop | WinVault Keyring (Windows Credential Manager) | ✅ 跨进程持久化，App 重启自动恢复 |

**恢复流程：**
```
App Startup
  ↓
AuthNotifier.restore() / AuthController.restore()
  ↓
TokenStorage.getTokens()
  ↓
有 Token → Authenticated
无 Token → Unauthenticated
```

**Token 过期处理：**
- API 401 → `handleUnauthorized()` → 尝试 Refresh → 成功则重试原请求
- Refresh 失败 → 清除 Session → 回登录页

## 4. Logout

**状态：PASS WITH LIMITATIONS**

| 端 | Token 清除 | WebSocket 关闭 | 确认对话框 |
|----|-----------|---------------|-----------|
| Android | ✅ | ✅ (AuthState → UNAUTHENTICATED 触发 realtime.disconnect()) | ✅ AlertDialog 确认 |
| Desktop | ✅ | ✅ (AuthState listener 触发 realtime.disconnect()) | ❌ 无确认，直接退出 |

**Backend Logout：**
- 吊销当前 Device 的所有 Refresh Token
- 设置 Device.revoked_at
- 写入登出审计日志
- 重复登出幂等安全（已吊销 token 返回 401）

**限制：**
- Desktop 退出登录无确认对话框，误触风险（P2）
- Logout 后 Access Token 在 TTL 内仍然有效（JWT 无状态设计，已知限制）
- 远程登出其他设备后，被登出端不会立即断开 WebSocket（无 device.revoked WS 事件）
