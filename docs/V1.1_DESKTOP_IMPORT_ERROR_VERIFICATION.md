# V1.1 Desktop Import Error Verification Report

**Date:** 2026-08-25
**Project:** Quiet Messenger
**Version:** v1.1.0
**Issue:** Desktop EXE ImportError — `attempted relative import with no known parent package`

---

## 1. Executive Summary

之前 Release Artifact Finalization 中声称 Desktop EXE 启动成功，但经严格验证发现：**旧 EXE 存在 ImportError，子进程立即崩溃，仅 onefile bootloader 存活，造成"运行中"的假象。**

**根因：** `app/main.py` 使用相对导入（`from .router.router import Router`），必须作为包模块运行（`python -m app.main`）。直接喂给 PyInstaller 作为入口脚本时，`__package__` 为 `None`，相对导入失败。

**修复：** 创建顶层入口脚本 `desktop/run.py`，无相对导入，导入 `app.main` 模块并调用 `main()`。PyInstaller 以 `run.py` 为入口，`app` 包可正常导入。

**最终结论：DESKTOP ARTIFACT READY**

---

## 2. Scenario A — Direct Script Invocation

### 命令
```bash
python app/main.py
```

### 结果
```
Traceback (most recent call last):
  File "E:\liaotianapp\desktop\app\main.py", line 26, in <module>
    from .router.router import Router
ImportError: attempted relative import with no known parent package
```

**判定: FAIL**

### 原因
`app/main.py` 第 26-41 行使用了 16 个相对导入：
```python
from .router.router import Router
from .theme import colors as C
from .api.api_client import ApiClient
# ... 等 16 个相对导入
```

相对导入要求模块作为包的一部分运行（`__package__` 必须设置）。直接运行脚本时 `__package__ = None`，导致 ImportError。

**正确运行方式：** `python -m app.main`

## 3. Scenario B — Packaged EXE (Old, app/main.py entry)

### 打包命令
```bash
pyinstaller --onefile --windowed --name "QuietMessenger" app/main.py
```

### 验证过程
1. 启动 EXE，观察进程
2. 用 `--console` 模式重新打包，捕获 stderr

### Console 版本输出
```

  File "main.py", line 26, in <module>
ImportError: attempted relative import with no known parent package
[PYI-20136:ERROR] Failed to execute script 'main' due to unhandled exception!
```

### Windowed 版本的假象
- 启动后 `Get-Process` 显示 1 个 QuietMessenger 进程
- 进程持续运行不退出
- **但这是 onefile bootloader 进程，实际 Python 子进程已因 ImportError 崩溃**
- 没有 GUI 窗口被创建（MainWindowTitle 为空）

**判定: FAIL (Release Blocker)**

## 4. Root Cause Analysis

| 层级 | 问题 |
|------|------|
| 代码结构 | `app/main.py` 使用相对导入，设计为包模块入口 |
| 打包方式 | PyInstaller 直接以 `app/main.py` 为入口，`__package__` 未设置 |
| 验证盲区 | onefile bootloader 在子进程崩溃后仍存活，之前的"运行 10 秒不退出"测试被误导 |
| 窗口检测 | 之前未检查 MainWindowTitle，仅检查进程是否存在 |

## 5. Fix — run.py Entry Point

### 新建文件: `desktop/run.py`

```python
"""Quiet Messenger Desktop — application entry point.

Top-level entry point for PyInstaller packaging and direct invocation.
Imports the `app.main` module (which uses relative imports internally)
and calls its `main()` function.
"""

from app.main import main

if __name__ == "__main__":
    raise SystemExit(main())
```

### 修复原理
1. `run.py` 无相对导入，可作为顶层脚本运行
2. PyInstaller 以 `run.py` 为入口，将 `desktop/` 目录加入 sys.path
3. `from app.main import main` 导入时，`app` 被识别为包，`__package__` 正确设置
4. `app/main.py` 内部的相对导入正常工作

### 新打包命令
```bash
pyinstaller --onefile --windowed --name "QuietMessenger" \
  --add-data "app/assets/sounds;app/assets/sounds" \
  --collect-submodules PySide6 \
  run.py
```

## 11. Lessons Learned

1. **onefile EXE 的进程存活 ≠ 应用正常运行** — bootloader 进程可能在子进程崩溃后仍存活。必须检查子进程数和 GUI 窗口标题。
2. **相对导入的模块不能直接作为 PyInstaller 入口** — 需要顶层 wrapper 脚本。
3. **console 模式是验证 ImportError 的可靠方式** — windowed 模式会隐藏 stderr。
4. **MainWindowTitle 是 GUI 是否创建的直接证据** — 比进程是否存活更可靠。
