## 6. 新端口规划（避免冲突）

### 6.1 原则
- 目标服务器 80/443 被宝塔占用 → 本项目 **不直接 listen 80/443**。
- 后端/WS 端口避开：3000/3001/5566/8201-8203/8765/8766/3306/6379/5432/17056/2222。
- PG 复用现有 5432（同机，独立 db/user），**不再起 PG 容器**。

### 6.2 推荐端口分配
| 用途 | 规划端口 | 说明 |
|---|---|---|
| 本项目 Nginx（HTTPS 对外） | **8443** | 避开 443（宝塔）；UFW 需新增放行 8443 |
| 本项目 Nginx（HTTP 重定向） | **8088** | 避开 80；301 → 8443 |
| Backend（容器内 8000，宿主不暴露） | expose 8000 | 仅 nginx 容器网络可达 |
| PostgreSQL | 5432（复用现有） | 独立 `chat_staging` 库 |
| WebSocket `/ws/v1` | 随 HTTPS 8443（nginx 同端口代理） | 与 API 同域名同源，无需独立端口 |
| SSH | 2222（保持） | 不改 |
| 宝塔 | 17056（保持） | 不改 |

> 备选：若中哥希望本项目也用标准 443，可走**宝塔反向代理**（在宝塔面板新增站点→反代到本项目 nginx 容器/backend），从而复用 80/443。但这涉及宝塔配置修改（属部署阶段，须单独授权，本轮不执行）。

### 6.3 docker-compose 调整要点（规划，不执行）
- `nginx.ports` 由 `"80:80"/"443:443"` 改为 `"8088:80"/"8443:443"`。
- `postgres` 服务**移除**（复用目标服务器现有 PG 16），backend `DATABASE_URL` 指向 `host.docker.internal:5432/chat_staging` 或自建 bridge 网络 + 外部 PG（同机非容器 PG 需用 `extra_hosts: host.docker.internal:host-gateway`）。
- 或保留 PG 容器但改端口 `5433:5432`（避免与现有 5432 冲突）——但会额外吃内存（资源紧张，不推荐）。
