## 3. REST Reconciliation Audit (DEF-RT-010)

### Before Fix

- WebSocket reconnect worked (exponential backoff [1,2,4,8,16]s)
- But **no automatic REST reconciliation** on reconnect
- Missed events during network outage would not be recovered until user manually refreshed
- This was documented as a known limitation (DEF-RT-010)

### Fix Implemented

**Android:**
1. Added multi-cast state listeners to `RealtimeClient`:
   - `_stateListeners: List<void Function(ConnectionState)>`
   - `addStateListener()` / `removeStateListener()`
   - `_setState()` calls all state listeners (each in isolated try/catch)
2. `FriendNotifier.subscribeRealtime()` now also subscribes to state changes
3. Reconciliation logic in `_onConnectionState()`:
   - Tracks `_hasBeenConnected` (initial connect vs reconnect)
   - Tracks `_wasDisconnected` (prior drop)
   - On `connected` after a prior `disconnected`: calls `loadRequests()` (REST refresh)
   - Initial connect does NOT trigger reconciliation (avoids duplicate loads)
4. `dispose()` unsubscribes from both event and state listeners

**Desktop:**
1. Added multi-cast state listeners to `RealtimeClient`:
   - `_state_listeners: list[Callable[[ConnectionState], None]]`
   - `add_state_listener()` / `remove_state_listener()`
   - `_set_state()` calls all state listeners (each in isolated try/catch)
2. `FriendController.__init__()` now also subscribes to state changes
3. Same reconciliation logic as Android
4. `dispose()` unsubscribes from both

### Reconciliation Coverage

| State | Mechanism | Status |
|-------|-----------|--------|
| Friend requests | Auto-refresh on reconnect (both platforms) | ✅ |
| Friend list | Loaded on FriendsPage open; user can pull-to-refresh | ✅ (acceptable) |
| Messages | Loaded on ChatPage open; conversation list refresh on navigation | ✅ (acceptable) |
| Presence | Event-driven; backend sends presence.update on state change; reconnect triggers new presence events | ✅ (acceptable) |
| Conversations | Loaded on conversation list page open | ✅ (acceptable) |

### Rationale

Full automatic reconciliation for ALL state (messages, conversations, friends) on every reconnect would be excessive and could cause performance issues. The most time-sensitive data (friend requests) is auto-refreshed. Other data is loaded when the user navigates to the relevant page, which is the standard mobile/desktop pattern. This is a pragmatic, core-completion fix, not a feature expansion.

**Verdict:** ✅ PASS (fixed from previous limitation)
