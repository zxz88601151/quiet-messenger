## 0. 一句话结论

**APK 无法登录是「配置 + 部署 + Android 端」三重问题叠加，与后端 Auth/Token 代码无关。**

后端 API 经真实 E2E 验证（注册→登录）完全正常返回合法 JWT。真正卡死登录的是三道独立的墙：

1. **Android release APK 缺少 `INTERNET` 权限** → 系统直接禁止任何联网，登录请求根本发不出去。
2. **APK 写死的 API 地址 `http://192.168.3.200:9080` 在部署侧根本不存在** → 即便加上 INTERNET 权限，也连到一个没有监听的端口。
3. **Staging 部署未真正启动（无 `.env` → 部署脚本 exit 1，且 nginx 未暴露 9080）** → 正确的访问路径（HTTPS 443 / 内部 8000）与 APK 配置完全错位。

## 4. 三道独立根因详解

### 根因 A（第一性，Android 端）：release APK 无 INTERNET 权限
- `android/app/src/main/AndroidManifest.xml` **未声明** `<uses-permission android:name="android.permission.INTERNET"/>`。
- 该权限仅在 `src/debug/` 和 `src/profile/` 的 manifest 中（Flutter 模板默认）。
- Manifest 合并规则：release 构建只合并 `main/` + `release/` 的 manifest，`debug/` 的权限**不会**进入 release APK。
- **后果**：Android 系统对无 INTERNET 权限的应用禁止所有网络 socket。登录请求的 `Dio` 调用会在连接阶段被系统拒绝（通常表现为 `SocketException: Permission denied` 或连接超时），用户看到"无法登录"。
- 这是**无论后端是否在线都会失败**的第一道墙。

### 根因 B（配置，App 端）：API endpoint 指向不存在的地址
- `api_config.dart` 中 `staging` = `http://192.168.3.200:9080`。
- 实测 `192.168.3.200:9080` **Connection refused**（端口无监听）。
- 该主机上实际监听的是 `:80`/`:443`（nginx HTTPS）和内部 `:8000`（uvicorn，仅 bind 127.0.0.1）。
- 即使用户安装的是 release APK（staging 环境），其请求目标 `:9080` 在服务器侧根本不存在。
- 补充：该地址是**明文 HTTP** + **局域网私有 IP**，即便端口通，也不符合任何生产/公网形态。

### 根因 C（部署，服务端）：Staging 未按设计启动
- `deploy/scripts/run-backend-staging.sh` 第一行检查 `if [[ ! -f .env ]]; then exit 1`，而 `backend/.env` **不存在**（仅有 `.env.example`）。→ 按脚本部署时 staging 后端根本起不来。
- `deploy/nginx/nginx.conf` 只 `listen 80` + `listen 443 ssl`，**没有任何 `listen 9080` 的 server block**。APK 期望的 9080 从未被任何服务暴露。
- 当前在 `192.168.3.200` 上实际运行的是：nginx(:80/443) + 一个 bind 127.0.0.1:8000 的后端（由 `E:\liaotianapp\backend` venv 启动，无 `.env` → 默认 SQLite `chat_dev.db`、ENVIRONMENT=development、JWT_SECRET 为空串）。
- 设计中的 **PostgreSQL** 从未被接入（staging 启动依赖 `.env` 里的 `DATABASE_URL=postgresql+...`，缺失即退回 SQLite）。

### 次要问题 D（数据）：测试账号可能不存在
- `chat_dev.db` 仅含 1 个历史账号 `alice`（13800000001）。
- 若用户手中的测试账号未注册进当前 SQLite 库，即使前 3 道墙修好，登录也会因 `INVALID_CREDENTIALS` 失败（后端统一不暴露账号是否存在）。

## 6. 修复建议（仅记录，本轮不执行）

> 以下为修复路线，按 AUDIT ONLY 纪律**不实施**，待授权后单独执行。

1. **【Android，必做】** 在 `android/app/src/main/AndroidManifest.xml` 的 `<manifest>` 根节点下添加 `<uses-permission android:name="android.permission.INTERNET"/>`（并视需 `ACCESS_NETWORK_STATE`）。这是让任何网络请求能发出的前提。
2. **【Android，必做】** 为 staging/release 配置明文 HTTP 允许或改用 HTTPS：在 `main/AndroidManifest.xml` 的 `<application>` 加 `android:usesCleartextTraffic="true"`（仅限内网 staging 验证），**生产必须改用 HTTPS 真实域名并移除明文放行**。
3. **【配置，必做】** 修正 `api_config.dart` 的 staging 地址：要么指向 nginx 的 `https://<真实域名>`（生产），要么内网验证时指向实际可达地址（如 `http://192.168.3.200`（80/443）→ 但需 nginx 暴露 `/api/` 且后端真实连 PG）。**`:9080` 必须删除**。
4. **【部署，必做】** 创建 `backend/.env`（从 `.env.example` 复制），填入真实 `DATABASE_URL=postgresql+psycopg://...`、`JWT_SECRET`、`ENVIRONMENT=staging`，并按 `run-backend-staging.sh` 跑 `alembic upgrade head` + uvicorn。`nginx.conf` 需确认 `/api/` 已代理到 backend:8000（当前配置已含，但需确保容器/服务名可达）。
5. **【数据库，建议】** 接入设计的 PostgreSQL 并建立用户（注册或导入测试账号），避免 SQLite 多文件隔离导致的"账号找不到"。
6. **【构建，建议】** 明确 APK 交付类型：当前磁盘只有 `app-debug.apk`。若交付 debug APK，其走 `development` = `127.0.0.1:8000`——在**手机**上这是手机自身 localhost，永远连不到后端，同样无法登录。需重新决策 debug（改 development 地址为可达后端）还是 release（修 staging 地址 + 权限 + HTTPS）。
