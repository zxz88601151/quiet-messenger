## 1. Scope（范围）

Phase 3E 目标：建立真实 **Conversation → Message → 双端实时 / 可靠展示** 闭环。

仅实现：
- 会话内消息 REST 发送 / 历史拉取（游标分页）
- WebSocket `message.created` 实时广播（仅发给 peer）
- 双端（Flutter Mobile + PySide6 Desktop）消息列表渲染、气泡（mine/peer）、乐观发送 + 确认、失败重试
- 客户端去重（按 message id）、断线后 REST 历史恢复

严格不实现（Phase 3E §3，均冻结至后续 Phase）：typing / read receipt / reaction / reply / edit / recall /
file / image / voice / video / group / AI / push / 全局消息 / 系统公告。

## 5. WebSocket（实时层）

- 鉴权：`Authorization: Bearer <token>` **请求头**；无效 → `close 4401`；`user_id` 取自 JWT sub
- 隔离：`ConnectionManager.send_to_user(user_id, ...)` 按 user_id 单播，**无跨用户事件泄漏**
- 广播：`send_message` 仅 `send_to_user(peer_id, message.created)`；不回发发送者
- 客户端：Flutter 多监听 + 指数退避重连；Desktop 单 `on_event` 槽（单活跃会话模型）

---

## 6. Message Consistency（消息一致性）

- **sender_id 为真**：服务端 `user.id` 赋值，不可前端伪造（安全基线）
- **client_message_id 是幂等键，不是归属标记**：后端 `MessagePublic` **对双方都返回** `client_message_id`
  （用于前端断线重发去重）。**归属判定唯一正确规则 = `sender_id == current_user_id`**。
  > ⚠️ 此规则在 Phase 3E 双端被误用为 `client_message_id != null`（见 Phase 3F P2 缺陷与修复）。
- **去重**：客户端按 `message.id` dedup；后端按 `(conversation_id, client_message_id)` 唯一约束
- **顺序**：`created_at` 显式微秒精度（避免同秒批量插入时间戳碰撞导致分页丢消息，social_service.py:462）

## 8. Security（安全）

- 401/403/404/400 统一错误结构（API_CONTRACT §7）：`{ error: { code, message, status } }`
- **sender_id 服务端赋值**，不可越权伪造（social_service.py:459）
- **WS token 不进 URL**，仅请求头（ws.py）
- **ConnectionManager 按 user_id 隔离**，无跨用户事件泄漏
- 无 Admin 接口；非会话成员发送 / 读取 403；不存在会话 404
